# Требования к рождению и редактированию персонажа

## Выполнено в OpenAPI 0.3.0

- Новая генерация начинается с возраста 0; старые сохранения остаются в своём возрасте.
- Frontend сохраняет имя и внешность через `PATCH /sessions/{id}/character`.
  Для `local` также доступны здоровье и интеллект. Применяется полный ответ
  той же сессии; версия, повторы и конфликты обрабатываются общим клиентом.
- Полный список параметров виден в анкете и редакторе. Остальные поля API
  пока не разрешает менять. Неизвестные значения помечаются «Нет данных».
- Проверена смена имени через Docker backend и восстановление после F5.

Ниже сохранены исходные требования и ограничения версии 0.2.0 для контекста.

Пользователь ожидает анимацию создания, редактирование параметров до начала
игры и последовательную жизнь с возраста 0 лет. Генерация уже подключена к
OpenAPI 0.2.0. Анимация frontend показывает результат country/countryCode
из полученного сохранения.

## Исходные ограничения backend 0.2.0

В OneInEightBillionEngine.generate выполняется live с lang и seed.
Первый ответ содержит возраст первого решения, например 2 или 3 года.
Backend записывает этот возраст, историю и курсор в PostgreSQL.
Методов редактирования профиля/характеристик в OpenAPI 0.2.0 нет.
Тело POST /api/v1/sessions/generated ограничено пустым объектом.

## Начало с рождения

- Создать реальное состояние возраста 0 с соответствующим курсором движка,
  начальными характеристиками и только событиями рождения.
- Проверить поддерживаемый поставщиком способ получения такого состояния.
  Документация /live описывает продвижение до первого решения при создании.
  Поддержку альтернативного сценария необходимо подтвердить проверкой.
- Простое изменение age на 0 не перематывает курсор движка. Для корректного
  продолжения состояние и курсор должны соответствовать друг другу.
- Если реализуется воспроизведение ранних лет из истории, API должен явно
  возвращать сохранённые состояния по годам, их характеристики и прогресс.
  Продолжение после F5 должно учитывать реально показанные годы и события.
- Ответ на каждое advance должен соответствовать следующему игровому этапу.
  Вопрос появляется при достижении его возраста.

## Редактирование до начала игры

- Определить поддерживаемые изменения профиля, места рождения, семьи
  и начальных характеристик с учётом возможностей внешнего движка.
- Добавить в OpenAPI команду редактирования/перегенерации с expectedVersion
  и Idempotency-Key и ответом с полным актуальным сохранением.
- Если изменение требует нового курсора или перегенерации, выполнить это
  на backend с согласованными историей, профилем, возрастом и токеном.
- Вернуть возможности редактирования для каждого поля и причину ограничения,
  если поставщик не поддерживает изменение.
- Зафиксировать момент старта игры, если редактирование разрешено только
  до нажатия «Начать жизнь». Проверять это на сервере.
- Сохранять изменения в PostgreSQL. GET после F5 возвращает ту же анкету.
- Поля, которые API не предоставляет (например aura/appearance), не заполнять
  случайными моковыми значениями.

## Приёмка

1. «Играть» показывает анимацию и анкету нового персонажа.
2. Изменение поддерживаемого поля сохраняется и переживает F5.
3. «Начать жизнь» открывает тот же id с возрастом 0 и соответствующей историей.
4. Время проходит последовательно, будущие события ещё не отображаются.
5. Первый выбор появляется в нужном возрасте.
6. Сохранения старого формата остаются доступными.

Текущая реализация перечислена в начале документа. Расширение остальных
редактируемых полей требует обновления контракта backend.
