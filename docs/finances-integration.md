# Бюджет: OpenAPI 0.11.0

## Управление доходами и расходами

Карточки «Доходы» и «Расходы» открывают отдельные окна в существующей области между шапкой и нижней навигацией. Их прежнее оформление сохранено. Окно останавливает игровое время, при переходах между разделами не размонтируется, сохраняет позиции прокрутки и возвращает фокус без прокрутки страницы.

- `GET /budget/income`, `/expenses`, `/jobs`, `/side-jobs`, `/businesses`, `/strategies`, `/assets` загружаются для текущего sessionId. Все ответы проверяются декодером, включая nullable поля и обёртки неподдерживаемых сохранений.
- `GET /budget/assets/{assetId}/sale-preview` показывает серверные цену, погашение залога, чистое поступление, прекращаемое содержание и прогноз. Версия предпросмотра передаётся при подтверждении продажи.
- `POST /budget/actions` отправляет только `expectedVersion`, `action`, `optionId`. Используются общий клиент, гостевая cookie, блокировка повторного нажатия и неизменная подготовленная команда для сетевого повтора.
- Поддержаны APPLY_JOB, REQUEST_RAISE, QUIT_JOB, TAKE_SIDE_JOB, QUIT_SIDE_JOB, OPEN_BUSINESS, SET_STRATEGY и SELL_ASSET. Увольнение требует отдельного подтверждения.
- Полный Session из ответа заменяет состояние. APPLIED выполняет переход к обновлённым доходам/расходам; DECLINED показывает отказ и оставляет возможность выбрать другой вариант. Перечитывание ресурсов происходит даже при неизменной версии DECLINED.
- При конфликте версии или недоступности действия перечитываются Session и открытые ресурсы. Отклонённая команда автоматически не повторяется. Продажа требует нового подтверждения после обновления предпросмотра.
- Внутри открытого окна видны ошибки и повтор исходной команды после потери ответа, включая вложенное подтверждение увольнения. В детстве, при pendingDecision и COMPLETE действия заблокированы.
- Ставки работы показываются в месяц, как возвращает контракт. Фактические доходы и расходы — за 12 месяцев. Клиент не вычисляет финансовые итоги и не применяет последствия повторно. BUSINESS показывается отдельно от зарплаты.
- Аренда не изображается работающей механикой. Cash и deposit доступны по серверным ограничениям; остальные стратегии видны с причиной недоступности. Покупки со статусом SOLD сохраняются в истории без будущего содержания.
- Старые покупки, внешние жизни с PPP_USD и отдельный моковый сценарий сохранены. В неподдерживаемом сохранении новое окно показывает объяснение сервера.

### Проверка 27.11.2026

`npm test`, `npm run typecheck`, `npm run lint`, `npm run build` и отдельная Docker-проверка:

```powershell
node tests/budgetManagement.integration.mjs
```

Интеграционный тест создаёт отдельного гостя и сгенерированную local-жизнь, доводит её до взрослого возраста. Проверяет все GET, сверку итогов, cash/deposit, блокировку облигаций, найм, подработку, увольнения, повышение, покупку и продажу имущества, SOLD, запрет повторной продажи, открытие бизнеса, неизменность игрового месяца, повтор ключа и восстановление той же сессии. Тестовые жизни остаются под отдельными гостями. Повышение и наём могут законно вернуть DECLINED; тест учитывает этот исход.

В браузере проверены реальные данные детской жизни и блокировка действий до 18 лет. На изолированных тестовых данных через настоящий useServerLife проверены взрослые окна, вложенное подтверждение увольнения, изменение стратегии, предпросмотр продажи, мобильные размеры 430/320 px, отсутствие горизонтального переполнения окна и один запрос после двойного нажатия. Временная страница для проверки удалена.

Ручная проверка:

1. Продолжить взрослую local-жизнь, поставить паузу, открыть «Бюджет» → «Доходы».
2. Открыть вакансии, проверить фильтры и причины недоступности, отправить отклик. Проверить сообщение APPLIED или DECLINED и новые данные.
3. Проверить повышение, подработку, отмену и подтверждение увольнения. Другие источники дохода должны сохраниться.
4. Сменить cash/deposit. Недоступные стратегии не должны выбираться.
5. Открыть «Расходы», проверить категории, обязательства и условный прогноз. Выбрать имущество, изучить предпросмотр и подтвердить продажу.
6. Проверить остаток, историю, статус «Продано», открытие бизнеса и восстановление после F5.
7. При отключённой сети повторить запрос после восстановления. Не должно быть второго списания. При изменении жизни в другом окне подтвердить действие заново после обновления данных.

## Прежние покупки: OpenAPI 0.5.0

Frontend использует текущую сессию и существующий `sessionsApi`. В разработке запросы идут через `/api`, прокси Vite направляет их на `http://127.0.0.1:8081`. Backend и ключ внешнего движка не менялись.

- `/finances` загружается при первом открытии вкладки и обновляется после новой версии сессии: покупки, перехода года, ответа на решение или восстановления.
- `/spending/{categoryId}` возвращает подписи, предложения, цены, ограничения и прогноз остатка. Окно использует эти данные, без подстановки моковых цен.
- `/purchases` принимает `expectedVersion` из каталога, `categoryId`, `itemId` и `petName` для питомцев. Цена, баланс и эффекты в запрос не передаются.
- Подготовленная команда сохраняет один `Idempotency-Key` и неизменное тело для повтора после потери ответа. Двойное нажатие блокирует общий контроллер запросов. При `VERSION_CONFLICT` перечитывается сессия и затем бюджет/каталог; покупка автоматически заново не применяется.
- Успешный ответ покупки заменяет сессию; бюджет перечитывается. Местоположение берётся из `finances.location`, место рождения сохраняется в `character.birthplace`.
- Игровое время останавливается на время окна. Изменение версии от покупки не сбрасывает прогресс текущего года. При закрытии сохраняется позиция прокрутки.
- Для `local` используются игровые рубли. Для `1in8b` показываются международные доллары по ППС, `null` отображается как «Нет данных», предложения доступны для чтения. `netWorth` не используется как доступный баланс.
- Моковый сценарий и его данные сохранены отдельно от серверного.

## Проверки

```powershell
npm test
npm run typecheck
npm run lint
npm run build
node tests/finances.integration.mjs
```

Последняя команда требует работающий Docker backend на порту 8081. Она создаёт отдельного гостя и локальную тестовую жизнь, не обращается к внешнему движку и не использует его квоту. Тестовое сохранение остаётся в локальной базе под этим отдельным гостем.

Интеграционный тест проверяет девять каталогов; покупку хомяка в семь лет (1 200 → 600 ₽); повтор с тем же ключом без второго списания; конфликт версии; возрастные ограничения; недостаток средств; ежегодное содержание; покупки во всех девяти категориях; обновление местоположения; запрет повторной покупки уникальных вещей; завершение курса и остановку покупок в 22 года.

В браузере проверены двойное нажатие (один POST покупки), обновление характеристик/бюджета, восстановление после F5, сохранение прокрутки и прогресса года, серверные окна на ширинах 320 и 430 px, а также неизвестные финансовые поля сохранённой жизни `1in8b`.
